1. แจ้งเตือนทางอีเมล

Backend เป็นผู้ตัดสินใจส่งจริงเสมอ — ตรวจ settings.emailNotif ฝั่งเซิร์ฟเวอร์ก่อนคิวงาน แม้ client จะเรียกมา ถ้า toggle ปิดต้องตอบ 202 พร้อม skipped: true และไม่ส่งอีเมล

POST /notifications/email
Request  { "event": "registration.created", "to": "organizer@nu.ac.th",
           "lang": "th", "vars": { "student": "…", "activity": "…", "date": "…", "seatsLeft": 12 } }
201      { "id": "em-9f2a1c", "status": "queued", "provider": "sendgrid", "createdAt": "…" }
202      { "skipped": true, "reason": "EMAIL_NOTIFICATIONS_OFF" }
422      error.code = "UNKNOWN_EVENT" | "INVALID_RECIPIENT"
GET /notifications/email?status=&event=&limit=50&cursor=
200      { "items": [ { "id","event","to","lang","subject","status","attempts",
                        "createdAt","sentAt","error" } ], "nextCursor": null }
status ∈ queued | sending | retrying | sent | failed | skipped
POST /notifications/email/{id}/retry
200      { "id": "em-9f2a1c", "status": "queued", "attempts": 4 }
409      error.code = "NOT_RETRYABLE"   (รายการที่ status = sent หรือ skipped)

Retry policy: exponential backoff 4 ครั้ง (0s / 30s / 2m / 10m) แล้วตั้ง failed · เก็บ log ไม่น้อยกว่า 90 วัน · webhook ของผู้ให้บริการ (POST /webhooks/sendgrid) อัปเดต delivered / bounced ย้อนกลับเข้า log

เหตุการณ์และ template — ทุก template มีคู่ th/en เลือกตาม users.language ของผู้รับ:

event ผู้รับ ตัวแปรใน template
registration.createdผู้จัดstudent, activity, date, seatsLeft
cancellation.requestedผู้จัดstudent, activity, reason
approval.changedนิสิตactivity, status
hours.approvedนิสิตactivity, hours
certificate.issuedนิสิตactivity, ref
password.changedเจ้าของบัญชีtime, device
backup.failedแอดมินfreq, time, error

1.9 ลบข้อความแชท

DELETE /messages/{id}       { "scope": "me" | "all" }
       200  { "id","scope","deletedAt" }
       403  error.code = "DELETE_WINDOW_EXPIRED"   (scope=all เกิน 24 ชม. และไม่ใช่แอดมิน)
       403  error.code = "NOT_MESSAGE_OWNER"       (ไม่ใช่เจ้าของ และไม่ใช่แอดมิน)
       scope=all ของแอดมิน → บันทึก audit log (actor, target, conversationId)

DELETE /conversations/{id}   200 { "id","scope":"me","deletedAt" }
       ซ่อนเฉพาะฝั่งผู้เรียก (เก็บ hidden_at) — ข้อความใหม่ที่ ts > hidden_at ทำให้ห้องกลับมา

POST   /messages/bulk-delete { "olderThanMonths": 6, "dryRun": true }
       200  { "deleted", "conversations", "olderThanMonths", "runAt" }
       dryRun=true คืนจำนวนที่จะลบเพื่อยืนยันก่อน (ไม่ลบจริง)
       เฉพาะบทบาท admin · บันทึก audit log ทุกครั้ง

ลบเฉพาะฝั่งฉันเป็น soft delete — เก็บ deleted_for[] ต่อข้อความ ไม่ลบแถวจริง เพื่อให้อีกฝ่ายยังเห็น · ลบสำหรับทุกคน เก็บ tombstone (deleted_all=true) ไม่ลบแถว เพื่อคงลำดับ/จำนวนข้อความไว้ · ปุ่ม "เลิกทำ" ฝั่ง client หน่วง commit 5 วินาที ควรส่ง request จริงหลังหมดเวลาเท่านั้น

5. เปลี่ยนรหัสผ่าน

POST   /auth/password      { "currentPassword": "…", "newPassword": "…" }
       200  { "changedAt": "…", "sessionsRevoked": 2 }
       401  error.code = "INVALID_CREDENTIALS"   (รหัสผ่านปัจจุบันไม่ถูกต้อง)
       422  error.code = "WEAK_PASSWORD" | "SAME_PASSWORD"
       429  error.code = "TOO_MANY_ATTEMPTS"     (5 ครั้ง / 15 นาที ต่อบัญชี)

เก็บด้วย bcrypt cost 12 (หรือ argon2id) · เทียบรหัสเดิมด้วย constant-time compare · เกณฑ์ขั้นต่ำ 8 ตัวอักษร มีทั้งตัวอักษรและตัวเลข · เมื่อสำเร็จ: invalidate ทุก session ยกเว้นอุปกรณ์ปัจจุบัน, ออก session id ใหม่ (ป้องกัน fixation), ส่ง password.changed ทางอีเมล และเขียน audit log

8. เช็กลิสต์ automated tests

· อีเมล — toggle เปิด: เกิด event → มี 1 record status sent; toggle ปิด: ไม่มี record ใด ๆ ที่ status ≠ skipped
· อีเมล — provider ตอบ 503 สามครั้งแล้วสำเร็จ: attempts = 4, status = sent; ล้มเหลวครบ: status = failed และปุ่มส่งซ้ำทำงาน
· อีเมล — ผู้รับ language = en ได้ subject/body ภาษาอังกฤษ
· Backup — scheduled job รันตามรอบจริงที่ตั้ง; retention เกินจำนวนแล้วชุดเก่าถูกลบ
· Backup — ล้มเหลว → record status failed + ส่ง backup.failed + POST /admin/reset ตอบ 409
· ปฏิทิน — ไฟล์ .ics ผ่าน validator RFC 5545; ยกเลิกกิจกรรม → SEQUENCE เพิ่มและ STATUS = CANCELLED
· กยศ. — เปลี่ยน goal 36 → 40 แล้ว GET /students/{id}/hours ของทุกคนสะท้อนค่าใหม่ทันที
· ใบประกาศ — autoCert เปิด: อนุมัติชั่วโมง → มี PDF + ref ไม่ซ้ำ; ปิด: ไม่สร้างไฟล์
· รหัสผ่าน — รหัสเดิมผิด 401; รหัสใหม่อ่อน 422; สำเร็จ → session อื่นถูก revoke และมีอีเมลแจ้ง
· Idle — ครบเวลา → session id เดิมใช้เรียก API ไม่ได้ (401); กด “ใช้งานต่อ” → heartbeat ต่ออายุสำเร็จ
